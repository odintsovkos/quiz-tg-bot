# Пример банка вопросов

Здесь показано, как раскладывать файлы, если руководств и глав много.
Содержимое вопросов условное — это шаблон структуры, а не готовый банк.

```
data/questions/
  dev/                              Руководство разработчика (8.3)
    ch01-vstroennyj-yazyk.yaml
    ch08-rabota-s-zaprosami.yaml
    ap02-navigacionnye-ssylki.yaml
  admin/                            Руководство администратора (8.3)
    ch03-administrirovanie.yaml
  cs/                               Клиент-серверный вариант (8.3)
    ch02-ustanovka.yaml
  integration/                      Технологии интеграции 8.3
    ch04-web-servisy.yaml
```

Правила раскладки:

- **Каталог — руководство.** Имя каталога совпадает с `manual.id` внутри файлов:
  `dev`, `admin`, `cs`, `integration`.
- **Файл — глава.** Имя файла — идентификатор главы и слаг её названия:
  `ch08-rabota-s-zaprosami.yaml`. Приложения отличаются только префиксом
  идентификатора: `ap02-navigacionnye-ssylki.yaml`.
- **Идентификатор вопроса** собирается из тех же частей:
  `{manual.id}.{chapter.id}.{NNN}` — `dev.ch08.001`. Он уникален во всём банке
  и не меняется при правках: по нему живёт накопленная статистика.
- **Тема в боте** — `{manual.short} · {chapter.title}`, например
  «Разработчик · Глава 8. Работа с запросами». Один файл даёт ровно одну тему.

В этом каталоге лежат четыре файла, покрывающие все случаи:

| Файл | Что показывает |
|---|---|
| `dev/ch00-primer-glavy.yaml` | Обычная глава; кавычки вокруг значений, которые YAML понял бы как булево |
| `dev/ap00-primer-prilozheniya.yaml` | Приложение того же руководства; вопрос без `explanation` и с `active: false` |
| `admin/ch00-primer-glavy.yaml` | Вторая тема из другого руководства |
| `integration/ch00-primer-glavy.yaml` | Третье руководство; вариант ответа-число в кавычках |

Загрузить пример в базу можно как обычный банк:

```bash
python -m app.cli import-questions data/questions/example
```

Полное описание полей и правил — в [../README.md](../README.md).
