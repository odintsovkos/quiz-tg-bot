# Формат файлов с вопросами

Один файл — одна глава одного руководства. Файлы читает команда импорта
(`python -m app.cli import-questions data/questions/`) и загружает вопросы в SQLite.

## Раскладка каталогов

```
data/questions/
  dev/                              Руководство разработчика (8.3)
    ch01-vstroennyj-yazyk.yaml
    ch08-rabota-s-zaprosami.yaml
    ap02-navigacionnye-ssylki.yaml  приложения — префикс ap
  admin/                            Руководство администратора (8.3)
    ch03-administrirovanie.yaml
  cs/                               Клиент-серверный вариант (8.3)
    ch02-ustanovka.yaml
  integration/                      Технологии интеграции 8.3
    ch04-web-servisy.yaml
  element/                          1С:Предприятие.Элемент 9.3
```

Каталог — руководство, его имя совпадает с `manual.id` внутри файлов.
Имя файла — идентификатор и слаг главы: `ch08-rabota-s-zaprosami.yaml`.
Один файл даёт ровно одну тему в боте.

Готовый образец такой раскладки, который можно скопировать и импортировать, —
в [example/](example/).

## Структура файла

```yaml
manual:
  id: dev                              # префикс руководства, см. таблицу ниже
  title: Руководство разработчика      # полное название
  short: Разработчик                   # короткое, идёт в название темы
chapter:
  id: ch08                             # идентификатор главы внутри руководства
  title: Глава 8. Работа с запросами    # название темы в боте
  source: "Руководство разработчика (главы)/010 Глава 8. Работа с запросами.html"
questions:
  - id: dev.ch08.001
    text: Вопрос?
    difficulty: medium                 # easy | medium | hard
    options:
      - text: Верный вариант
        correct: true
      - text: Неверный вариант
    explanation: Пояснение, показывается после ответа.
    reference: 8.4.7.2. Использование слова «РАЗЛИЧНЫЕ»
```

Тема (категория) в боте собирается как `{manual.short} · {chapter.title}`,
например «Разработчик · Глава 8. Работа с запросами».

## Префиксы руководств

| Префикс | Руководство |
|---|---|
| `dev` | Руководство разработчика (8.3) |
| `admin` | Руководство администратора (8.3) |
| `cs` | Клиент-серверный вариант. Руководство администратора (8.3) |
| `integration` | Технологии интеграции 8.3 |
| `element` | 1С:Предприятие.Элемент 9.3 |

## Поля вопроса

| Поле | Обяз. | Правило |
|---|---|---|
| `id` | да | `{manual.id}.{chapter.id}.{NNN}`, уникален во всём банке, не меняется при правках |
| `text` | да | не более 300 символов |
| `options` | да | от 2 до 10 вариантов, каждый не более 100 символов |
| `options[].correct` | да | ровно у одного варианта `true` |
| `difficulty` | да | `easy`, `medium` или `hard` |
| `explanation` | нет | не более 200 символов |
| `reference` | нет | номер и название раздела главы, откуда взят факт |
| `active` | нет | по умолчанию `true` |

Лимиты 300 / 100 / 200 — это ограничения нативного quiz-опроса Telegram,
которым выдаются вопросы в группе. Импорт отклоняет файл при их превышении.

## Правила составления

- Один вопрос — один проверяемый факт из документации. Каждый факт должен
  находиться в главе, указанной в `chapter`; раздел указывается в `reference`.
- Неверные варианты должны быть правдоподобны: соседние ключевые слова,
  похожие механизмы, частые заблуждения. Варианты вида «ничего из перечисленного»
  не используются.
- Формулировка вопроса самодостаточна: её понятно читать в группе без контекста
  предыдущего вопроса.
- Фрагменты кода в тексте вопроса — не более одной строки, иначе не влезет
  в лимит 300 символов. Для длинных примеров вопрос переформулируется словами.
- `explanation` объясняет, почему верный вариант верен, а не повторяет его.
- Значения, которые YAML трактует особым образом, берутся в кавычки:
  `"NULL"`, `"Null"`, `"Истина"` не проблема, а вот `NULL`, `null`, `yes`, `no`,
  `on`, `off`, `~` без кавычек превращаются в пустое значение или булево.
  Это частая ошибка в вопросах по языку запросов.
- Значение, содержащее двоеточие с пробелом (`описания: одно`), тоже берётся
  в кавычки — иначе YAML считает его вложенным ключом и файл не читается.
- Значение, содержащее решётку после пробела (`Указать #Заказ`), берётся в кавычки —
  иначе YAML считает её началом комментария и обрезает значение. Это особенно
  коварно: варианты не ломают файл, а молча схлопываются в одинаковые.
- Вариант ответа, состоящий только из числа, берётся в кавычки: `"50"`, а не `50`.
  Иначе YAML вернёт число, а не строку. Числа в составе фразы («50 субконто»)
  кавычек не требуют.

Все эти случаи автоматически исправляет `python tools/fix_questions.py`,
а `python tools/validate_questions.py` проверяет результат.

## Валидация

Ошибки формата ловит импорт: он проверяет всю партию целиком, перечисляет все
найденные проблемы с указанием файла и `id`, и не загружает ничего, пока
файлы не исправлены.
