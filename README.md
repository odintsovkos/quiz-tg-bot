# QuizBot1C

Telegram-бот с викторинами по разработке на 1С. Публикует вопросы в групповой
чат по расписанию нативным quiz-опросом, ведёт личные викторины в переписке
с ботом и считает статистику участников. Вопросы составлены по документации
платформы «1С:Предприятие 8.3».

Стек: Python 3.11+, aiogram 3, SQLite (SQLAlchemy 2 + Alembic), APScheduler.

## Что умеет

- **В группе.** С заданной периодичностью и внутри окна активности публикует
  случайный вопрос, не повторяя его до конца круга. Балл получает каждый,
  кто ответил верно.
- **В личке.** Викторина из нескольких вопросов, одиночный случайный вопрос,
  выбор интересных тем, личная статистика и таблица результатов.
- **Дневные лимиты.** По умолчанию 5 запусков викторины и 20 случайных
  вопросов в сутки; отключаются администратором для всех или только для
  администраторов.
- **Кабинет администратора** прямо в боте: чаты, расписания, банк вопросов,
  лимиты, общие настройки, сводка, список администраторов.

## Установка

```bash
git clone <repository-url> quizbot1c
cd quizbot1c
python -m venv .venv
. .venv/Scripts/activate    # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"
```

Скопируйте `.env.example` в `.env` и заполните два обязательных значения:

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather);
- `OWNER_ID` — ваш Telegram-идентификатор (узнать можно у @userinfobot).
  При первом запуске этот идентификатор получает роль владельца.

Остальные переменные описаны в `.env.example` и имеют разумные значения
по умолчанию.

## Миграции

Схема базы создаётся Alembic:

```bash
python -m alembic upgrade head
```

Команда безопасна для повторного запуска. Откат — `python -m alembic downgrade base`.

## Вопросы

Банк вопросов в репозиторий не входит: он собран по документации платформы
и распространяется отдельно. В репозитории лежит только формат
([data/questions/README.md](data/questions/README.md)) и образец раскладки
на четыре файла из трёх руководств
([data/questions/example/](data/questions/example/)).

Свои вопросы кладите в `data/questions/`: каталог на руководство, файл на главу,
YAML в том же формате, что и в примере. Затем загрузите их в базу:

```bash
python -m app.cli import-questions data/questions
```

Импорт идемпотентен: повторный запуск обновляет изменившиеся вопросы и не
создаёт дубликатов. Вся партия загружается одной транзакцией — при любой ошибке
формата не загружается ни один вопрос, а отчёт перечисляет все найденные
проблемы с указанием файла и идентификатора.

Вопрос, исчезнувший из файлов, из банка не удаляется: вместе с ним потерялась
бы накопленная статистика. Добавлять и править вопросы можно и прямо в боте —
в кабинете администратора, раздел «Вопросы».

Другие команды:

```bash
python -m app.cli export-questions ./export   # выгрузка в формат импорта
python -m app.cli recalc-stats                # пересчёт агрегатов по ответам
```

## Запуск

```bash
python -m app.main
```

Процесс ведёт long polling и держит планировщик внутри себя. Остановка —
`Ctrl+C` или `SIGTERM`: бот дорабатывает текущие события, останавливает
планировщик и закрывает базу.

## Подключение группового чата

1. Добавьте бота в чат.
2. Выдайте ему право отправлять сообщения и опросы. Без права на опросы
   подключение будет отклонено: ответы на анонимный опрос нельзя связать
   с участником.
3. Отправьте в этом чате команду `/connect` от имени администратора бота.

Опросы публикуются неанонимными — иначе Telegram не присылает `poll_answer`
и начислить баллы невозможно. Участники видят, кто как ответил; бот
предупреждает об этом при подключении.

Отключение — `/disconnect` в том же чате. Статистика участников сохраняется.

## Настройка расписания и лимитов

Всё делается в кабинете: команда `/admin` в личке с ботом.

- **Чаты** — состояние и расписание каждого чата, приостановка и возобновление,
  отключение, немедленная публикация вопроса (расписание при этом не сдвигается).
- **Расписание** — периодичность, окно активности (`09:00-21:00`), набор
  категорий. Изменения применяются сразу, без перезапуска. Вне окна активности
  вопросы не публикуются и не копятся: после простоя выйдет не более одного.
- **Вопросы** — постраничный просмотр, карточка вопроса, правка полей,
  активация и деактивация, пошаговое добавление. Правки проходят ту же
  валидацию, что и импорт из файлов.
- **Лимиты** — режим («включены для всех» / «отключены для всех» / «отключены
  только для администраторов») и оба числовых значения.
- **Настройки** — размер сессии личной викторины, число строк в таблице
  результатов, таймзона суточного сброса.
- **Сводка** — участники, активные за сегодня, заданные вопросы, доля верных
  ответов, размер банка.
- **Администраторы** — только у владельца: назначение и снятие прав.

### Про режим «отключены только для администраторов»

В нём администраторы и владелец практикуются в личке без лимитов, но их личные
ответы не идут в общий зачёт — иначе безлимитная практика исказила бы таблицу.
Ответы тех же участников на групповые вопросы учитываются как у всех.

Смена режима не пересчитывает прошлое: у каждого ответа флаг учёта
проставляется один раз, в момент записи.

## Сутки и статистика

Дневная статистика и дневные лимиты относятся к календарному дню в действующей
таймзоне (по умолчанию `Europe/Moscow`). Никакой ночной задачи обнуления нет:
новый день начинается сам собой, потому что у первого ответа после полуночи
другая дата. Поэтому остановка бота на полночь ничего не ломает, а итоги
прошедших дней остаются в истории.

Смена таймзоны из кабинета влияет только на дальнейший отсчёт — сохранённые
дневные итоги не пересчитываются.

## Резервное копирование

Все данные — в одном файле SQLite (`DB_PATH`, по умолчанию
`data/quizbot.sqlite3`). База работает в режиме WAL, поэтому рядом лежат файлы
`-wal` и `-shm`.

Копию лучше снимать средствами SQLite, не останавливая бота:

```bash
sqlite3 data/quizbot.sqlite3 ".backup 'backup/quizbot-$(date +%F).sqlite3'"
```

Простое копирование файла тоже подойдёт, но только при остановленном процессе —
и обязательно вместе с файлом `-wal`.

Восстановление: остановить бота, положить копию на место `DB_PATH`, запустить.
Копию стоит снимать перед каждым обновлением — это и есть точка отката.

## Docker

```bash
cp .env.example .env    # заполнить BOT_TOKEN и OWNER_ID
docker compose up -d --build
```

Файл SQLite лежит на именованном томе `quizbot-data` и переживает пересоздание
контейнера. Каталог `data/questions` примонтирован только для чтения — чтобы
обновить банк, поправьте файлы на хосте и выполните:

```bash
docker compose exec bot python -m app.cli import-questions data/questions
```

Миграции применяются автоматически при старте контейнера.

## Разработка

```bash
python -m pytest          # весь набор тестов
python -m ruff check app tests
python -m mypy            # строгий режим на пакет app
```

Тесты не обращаются к Telegram и работают на временных файлах SQLite.

Архитектура: `handlers → services → repositories → models`, зависимости идут
только вниз. Правила начисления баллов, выбора вопроса и суточных границ
живут в сервисах и проверяются без Telegram. Подробности решений —
в `openspec/changes/archive/2026-09-05-add-quiz-bot-mvp/design.md`, поведение по каждой
возможности — в `openspec/specs/`.
