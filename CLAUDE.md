# QuizBot1C

Telegram-бот с викторинами по разработке на 1С. Python + aiogram 3 + SQLite.
Вопросы составляются по локальной копии документации в каталоге `Документация/`.

В проекте две независимые дорожки. Они не пересекаются — работайте с той,
о которой просит пользователь.

## Дорожка 1. Код бота (OpenSpec)

Бот написан и работает. Источник истины по поведению — `openspec/specs/`:
шесть capability (`bot-core`, `private-quiz`, `group-quiz`, `admin-console`,
`quiz-content`, `scoring-and-stats`). Незакрытых изменений нет, история —
в `openspec/changes/archive/`.

Проверки перед сдачей работы: `python -m pytest -q`, `python -m mypy app`,
`python -m ruff check app tests`. Все три должны быть чистыми.

Слои: `handlers → services → repositories → models`. Обработчик не ходит в БД
мимо репозитория и не считает бизнес-правила сам.

| Каталог | Что внутри |
|---|---|
| `app/bot/` | Роутеры по зонам, хендлеры, клавиатуры, тексты, middleware |
| `app/services/` | Правила: сессии, лимиты, темы, расписание, статистика, импорт |
| `app/repositories/` | Доступ к данным |
| `app/models/` | ORM-модели; `migrations/` — alembic |
| `app/core/` | Конфигурация, движок БД, планировщик, логирование, время |

### Как менять поведение

Спеки ведут код, а не наоборот. Новая возможность — `/opsx:propose`, затем
`/opsx:apply`, затем `/opsx:archive` (он же переносит дельты в `openspec/specs/`).
Правка плана незакрытого изменения — `/opsx:update`. Артефакты руками
в обход workflow не редактируются.

### Ключевые решения, чтобы не переспрашивать

- Групповая викторина — нативный quiz-опрос Telegram, балл всем ответившим верно.
- Дневная статистика обнуляется в полночь `Europe/Moscow`.
- Кабинет администратора живёт внутри бота, лимиты в личке настраиваются оттуда.
- **В личке единственный экран-якорь.** Переход между режимами — правка одного
  сообщения, а не новое. Весь личный вывод идёт через `app/bot/replies.py`;
  добавлять `message.answer` в обход нельзя. Исключение — лента сессии
  викторины: её сообщения учитываются в реестре и убираются при завершении.
- Команды участника в личке удаляются после обработки.
- Групповые чаты модели якоря не подчиняются: опрос правкой не заменить,
  а чужие сообщения бот удалять не вправе.

### Грабли, на которые уже наступали

- `DatabaseMiddleware` и `UserMiddleware` регистрируются как **outer**: inner
  отрабатывает после фильтров, и `IsAdmin`/`ConnectedChat` молча отвергают всё.
- Внутри обработчика нельзя открывать вторую сессию БД: транзакция события
  держит блокировку SQLite до возврата, и вложенная запись её не дождётся.
  Сервисы, которые зовут и из обработчика, и из планировщика, принимают
  `session` необязательным параметром.
- Задачи APScheduler живут в памяти и пересобираются при старте по таблице
  чатов. Хранилище задач в той же БД давало второго писателя и блокировки.
- Клавиатуры со списком из банка (темы, категории чата) обязаны листаться
  страницами: под сотню кнопок Telegram отвергает как слишком длинную разметку.
- Тесты, вызывающие обработчики напрямую, не проверяют ни фильтры, ни порядок
  middleware. Для этого есть `tests/test_dispatch.py` — событие идёт через
  настоящий диспетчер.

## Дорожка 2. Банк вопросов

Эта дорожка целиком локальная: `Документация/`, `tools/` и сами файлы вопросов
в git не выкладываются (см. `.gitignore`). В репозитории — только описание
формата и пример в `data/questions/example/`.

Что сделано и что дальше — в [data/questions/PROGRESS.md](data/questions/PROGRESS.md).
Реестр перечисляет все 89 тем (главы и приложения четырёх руководств 8.3),
файл под каждую и число вопросов. Пересобирается скриптом, вручную не правится.

### Рабочий цикл на одну тему

```bash
# 1. Оглавление главы — выбрать разделы, по которым будут вопросы
python tools/doc_sections.py "Руководство разработчика (главы)" "010 Глава 8. Работа с запросами.html" --heads

# 2. Выгрузить нужные разделы (номера через пробел)
python tools/doc_sections.py "Руководство разработчика (главы)" "010 Глава 8. Работа с запросами.html" 8.2 8.4.7 8.4.13

# 3. Прочитать tools/_out/sections.txt и написать data/questions/<prefix>/<id>-<слаг>.yaml

# 4. Проверить и обновить реестр
python tools/fix_questions.py && python tools/validate_questions.py && python tools/gen_progress.py
```

`doc_sections.py` сам разбирает cp1251 и вырезает разметку. Вывод всегда идёт
в файл — консоль Windows ломает кириллицу, читайте `tools/_out/*.txt` через Read.

### Формат и правила

Полное описание — [data/questions/README.md](data/questions/README.md). Кратко:

- Один файл — одна глава. Префиксы: `dev`, `admin`, `cs`, `integration`.
- `id` вида `dev.ch08.001`, стабилен при правках — по нему живёт статистика.
- Лимиты нативного quiz-опроса Telegram: вопрос 300 символов, вариант 100,
  пояснение 200. Валидатор их проверяет.
- **Ровно 4 варианта ответа**, один верный. Больше — только с обоснованием.
- У каждого вопроса `reference` — номер и название раздела, откуда взят факт.
- Язык — русский.

### Ловушки YAML

Все три встречались на практике, все чинит `fix_questions.py`:

- `NULL`, `yes`, `no`, `~` без кавычек → пустое значение или булево.
- Двоеточие с пробелом внутри значения → файл не разбирается целиком.
- **Решётка после пробела** (`Указать #Заказ`) → YAML считает её комментарием
  и молча обрезает значение. Файл при этом валиден, вопрос превращается
  в бессмыслицу. Ловится только проверкой вариантов на дубли — она в валидаторе есть.

### Принятые решения по наполнению

- Охват: главы **и приложения** четырёх руководств «1С:Предприятие 8.3».
  Документация «1С:Предприятие.Элемент» 9.3 в охват не входит.
- 10–15 вопросов на тему, для объёмных глав больше.
- Один вопрос — один проверяемый факт из указанной главы, не общие
  представления о 1С. Неверные варианты — соседние термины и механизмы
  из той же главы, а не выдумка.
- Приложения берутся выборочно. Хорошо пошли права доступа, особенности СУБД,
  навигационные ссылки, поисковые выражения. Пропущены конвертация из 7.7,
  XBase, автоформирование имён, а также перечень используемых компонентов
  (руководство администратора, приложение 8) — там вопросы выходят
  на заучивание версий и лицензий.
- Формулы и длинный код в лимит 300 символов не влезают — по таким темам
  спрашивайте принцип, а не расчёт.

## Инструменты

| Скрипт | Назначение |
|---|---|
| `tools/doc_sections.py` | Разделы главы из HTML документации в `tools/_out/` |
| `tools/extract_doc.py` | Извлечение текста из HTML (cp1251), используется остальными |
| `tools/validate_questions.py` | Проверка формата, лимитов, дублей id и вариантов |
| `tools/fix_questions.py` | Автоквотирование значений, которые YAML разберёт неверно |
| `tools/gen_progress.py` | Пересборка `data/questions/PROGRESS.md` по факту наличия файлов |

## Про длину сессии

Переписка перечитывается на каждом шаге, поэтому каждая следующая тема в одной
сессии дороже предыдущей. Наполнение банка удобно делать короткими сессиями:
`PROGRESS.md` хранит всё нужное, чтобы продолжить с чистого листа.
